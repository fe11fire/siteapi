# Изменения API и миграция

[Обзор проекта](../readme.md)

Эта страница фиксирует изменения относительно прежней реализации. Это не журнал разговора и не замена версии релиза: внешние приложения должны проверить свои вызовы перед обновлением.

| Было | Теперь | Что проверить |
|---|---|---|
| Ручная точка входа | App::run(root), генератор siteapi init | Сохраните свой bootstrap, если он нужен; App необязателен |
| Отсутствие настроек/middleware мешает простому запуску | App разрешает отсутствие каталогов | Ручной Settings::init() по-прежнему строгий |
| Отсутствующий middleware пропускается | Исключение при неверном классе/контракте | Исправить конфигурацию маршрутов |
| Несогласованность слеша перед query | Путь отделяется до нормализации | /about/ и /about/?x=1 совпадают |
| Нестрогое сравнение имён | Строгое сравнение | 01 и 1 — разные маршруты |
| Пустой массив не очищает параметры | [] очищает, null сохраняет | Проверить внутренние вызовы route() |
| get_Param_by_Name(): string/bool | mixed | Внутренние числа больше не приводятся к строке; null всё ещё трактуется как отсутствие |
| apply_Param_by_Name() дописывает HTML | Создаёт или заменяет mixed-значение | Накопление сообщений реализовать отдельно |
| selectSingle() | selectExactlyOne() | Переименовать вызовы; >1 строки — исключение |
| null в where означает SQL из ключа | null означает IS NULL | `['deleted_at IS NULL'=>null]` заменить на `['deleted_at'=>null]` |
| Произвольное условие через null | RawCondition(sql, bindings) | Отделить SQL-структуру от значений |
| selectCount() загружает строки | COUNT над подзапросом | В MySQL нужны уникальные имена колонок |
| PDO-соединение на каждый запрос | Одно ленивое соединение | Настройки после подключения его не меняют |
| Неявная строковая привязка PDO | Тип определяется PHP-значением | bool/int/null передаются явно; массивы/объекты запрещены |
| В логах SQL и значения | Метаданные, SQL только при debug | Секреты не вставлять непосредственно в SQL |
| Замена PDOException общим Exception | Исходное исключение сохраняется | Обработчики могут проверять PDOException |
| get()/get_Default() с ограниченным union | mixed + типизированные методы | Использовать getString/getInt/getBool/getArray там, где нужен контракт |
| Неверный JSON даёт предупреждение | Исключение с именем файла | Исправить повреждённые настройки |
| Старый Sender/Message/Recipient | Новая модель сообщений и объект Sender | Пересобрать вызовы по messaging.md |
| TelegramRequest и шаблоны отправки | Удалены | Входящие события не поддерживаются |
| Telegram SDK | Прямой cURL-клиент | SDK больше не нужен |
| Curl считает 4xx/5xx успехом | false + get_error() | Перенести обработку HTTP-ошибок в ветку false |
| Неудачное JSON-кодирование замалчивается | JsonException | Проверить данные payload и Vars |
| Вычисляемый SecretHelper с APP_ID | Случайный сессионный CSRF | Перезагрузить открытые формы, вызывать validate() |
| salt() длиной 8 | 32 hex-символа | Размер полей БД и внешние ограничения |
| Генератор игнорирует alphabet | Настройка учитывается, random_int | Завершающего дефиса больше нет |
| Неудачное чтение каталога маскируется | RuntimeException | Не считать отсутствующий каталог пустым |

Для кэша сохранены строки Redis/Memcached и новый enum API. Старые записи изолированы версионным пространством. Прямые статические вызовы адаптеров и старый CacheContract несовместимы: адаптеры теперь объектные и работают со строковым форматом. Поддержка Memcache удалена.

redirect() оставлен без кодирования для совместимости; новый код должен использовать redirectSafe(). Неизвестный логгер теперь даёт понятное исключение, init() принимает LoggerEnum или строку. Обязательные требования среды проверяются Composer.

## JSON-ответы Response

Добавлен SiteApi\Root\Http\Response для приложений с App::run(). Создание ответа не выводит JSON: используйте Response::ok(data: ['id' => 15])->throwSend(). Внутренний ResponseReady обрабатывается App отдельно от ошибок. Не перехватывайте его как обычную ошибку в прикладном catch(Throwable).

При переносе NVSR\Root\Response из лендинга замените импорт, добавьте ->throwSend() к вызовам и переведите ручной bootstrap на App::run(). Поля успешного ответа status/code/data и ошибки status/msg сохранены. Второй аргумент error() теперь HTTP-статус, а публичные дополнительные данные передаются через data и не объединяются с корнем JSON. По умолчанию error() возвращает HTTP 400 вместо прежнего 200: проверьте JS-обработчики ошибок HTTP. Существующий лендинг автоматически не обновляется.
