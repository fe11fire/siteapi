# Сервисы и безопасность

[Обзор проекта](../readme.md)

## Кэш

```php
<?php
use SiteApi\Root\Providers\Cache\{CacheProvider, CacheEnum};

CacheProvider::init(CacheEnum::REDIS, 'my-site');
CacheProvider::set('user:42', ['name' => 'Иван'], 300);
$result = CacheProvider::read('user:42');
if ($result['hit']) $user = $result['value'];
```

Есть Redis через Predis и Memcached через PHP-расширение. Без выбора используется Memcached. После init() доступность проверяется status(); сам init() соединение не проверяет. До инициализации status() возвращает false.

API: set, get, read, has, delete, remember. get() по умолчанию возвращает false при промахе; сохранённые false/null остаются значениями. read() возвращает независимые hit и value. Раздельные has/get подвержены истечению записи между вызовами.

TTL в секундах: 299 по умолчанию, 0 без срока, отрицательный запрещён. Для Memcached срок свыше 30 дней преобразуется в timestamp. Кэш может вытеснить запись раньше. remember() не блокирует параллельное вычисление.

Настройки: REDIS_HOST/REDIS_PORT либо redis.json, MEMCACHED_HOST/MEMCACHED_PORT либо memcached.json. По умолчанию redis:6379 и memcached:11211. Ошибки операций выбрасывают исключения; удаление отсутствующего ключа допустимо.

Значения сериализуются в версионный формат; пространство ключей отделяет приложения и старые записи. Поддерживаются PHP-типы и сериализуемые объекты, но не ресурсы/замыкания. Рекурсивные массивы и чрезмерная глубина отклоняются. Классы объектов нужны при чтении. Сервер кэша должен быть доверенным: unserialize вызывает методы объектов. Пользовательские методы сериализации отвечают за своё представление.

## Логирование

```php
<?php
use SiteApi\Root\Helpers\LogHelper;
use SiteApi\Root\Providers\Logger\{LoggerProvider, LoggerEnum};

LoggerProvider::init(LoggerEnum::FILE);
LogHelper::log('Order processed', ['order_id' => 125], 'orders');
LogHelper::error('Operation failed', ['operation_id' => '...']);
```

Допустимы enum и строки file/stdout. Неизвестное значение вызывает исключение, текущий провайдер сохраняется. По умолчанию файл: siteapilogs/ГОД/папка/месяц-день.log. Слеш в конце папки не требуется.

LogHelper маскирует известные именованные поля password/token/cookie и другие, но не умеет распознавать секрет в произвольной строке или числовом элементе массива. Подготавливайте контекст без секретов. debug-backtrace не содержит аргументов функций. Параметры send/tag сейчас не реализуют отправку уведомлений.

Файловый логгер использует общее создание каталогов с проверкой отказов и параллельного создания. Общий LogHelper может выбросить ошибку записи; ErrorHandler, DBHelper и клиенты доставки имеют собственные резервные пути. stdout предназначен прежде всего для консольных/контейнерных сценариев; его совместимость с конкретным веб-SAPI нужно проверять отдельно.

## JSON HTTP-клиент

```php
<?php
use SiteApi\Root\Clients\CURL\Curl;

$client = new Curl('https://example.com/api/items', [], 'POST', ['limit' => 10]);
if (!$client->exec()) {
    $reason = $client->get_error();
    $code = $client->get_http_code();
    return;
}
$data = $client->get_result();
```

Успех — HTTP 200–299 с JSON либо 204 без тела (result=null). Ошибки: connection_failed, timeout, http_error, invalid_json. HTTP-ошибка имеет приоритет; корректный JSON ошибки остаётся в result. При отсутствии ответа HTTP-код 0. Каждый exec сбрасывает предыдущий результат.

По умолчанию connect timeout 5 секунд, общий timeout 10 секунд. Payload кодируется с JSON_THROW_ON_ERROR. Клиент предназначен для JSON: произвольные HTML/текстовые ответы не считаются успешными. Страница ошибки автоматически не выводится, повторов нет.

В журнал не попадают URL, заголовки, payload, ответ и сырые ошибки cURL. Отказ журнала не меняет результат запроса. Отдельный ping() проверяет получение непустого HEAD-ответа, а не HTTP 2xx; не используйте его как проверку бизнес-успеха API.

## Защита форм

```php
<?php
use SiteApi\Root\Helpers\SecretHelper;

$csrf = SecretHelper::get('profile.save');
```

Передайте токен скрытым полем формы. В обработчике, до изменения данных:

```php
<?php
if (($_SERVER['REQUEST_METHOD'] ?? '') !== 'POST') {
    http_response_code(405);
    header('Allow: POST');
    return;
}
if (!SecretHelper::validate('profile.save', $_POST['_csrf'] ?? null)) {
    http_response_code(403);
    echo 'Не удалось проверить форму. Обновите страницу.';
    return;
}
```

Токен из 32 случайных байт хранится по имени в сессии; сравнение через hash_equals. Отсутствующий токен при validate() не создаётся. Сессия запускается лениво, активная используется повторно. Настройки cookie/хранилища задаются до первого вызова. Отказ запуска вызывает исключение, а не обход защиты.

Токен повторно используется, совместим с несколькими вкладками и сменой session ID при сохранении данных. Очистка сессии его инвалидирует. Helper не закрывает сессию; после session_write_close() новое обращение снова откроет её.

Это защита от подделки запросов с чужого сайта в контексте посетителя. Она не подтверждает использование именно интерфейса приложения, не останавливает всех ботов и не заменяет авторизацию. Не помещайте токен в URL/журнал и не кэшируйте персональную форму в общем кэше. Чтение JSON-тела и вызов validate() выполняет приложение.

## Файлы и строки

- make_Folder() создаёт вложенные каталоги; существующий каталог допустим, отказ — RuntimeException.
- list_Files()/list_Folders(): пустой каталог → []; отсутствие/ошибка чтения → исключение.
- list_Folders() возвращает полные относительные пути в глубину, учитывает subdir и subfolders=false. Ссылка на предка включается без повторного обхода; ссылки на другие каталоги могут вывести за исходный корень.
- remove_Folders_without_files()/remove_Folders_without_template() фильтруют список имён, а не удаляют каталоги с диска.
- generate_Code() использует random_int(), учитывает алфавит и регистр. length не включает дефисы; разделители идут между группами по пять символов, не в конце.
- plural_Form() выбирает форму по модулю числа, сохраняя знак в выводе; принимает три формы слова.
- salt() возвращает 32 hex-символа из random_bytes(16). Для паролей используйте password_hash().
